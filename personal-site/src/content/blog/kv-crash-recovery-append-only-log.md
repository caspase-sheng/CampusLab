我们这套 KV 引擎是 Bitcask 风格的，核心就一句话：磁盘上的段文件本身就是追加日志，没有单独的 WAL 文件，也没有快照模块。这个认识是后来才理顺的。一开始我脑子里默认「持久化 = WAL + 快照」，照那个结构去想，反而绕了远路，写出来的笔记和实现都对不上。

## 记录格式

一条记录是「21 字节固定头 + key + value」，全部小端：

```
[0:4]    crc32    uint32    校验范围 = 从 op 字节到 value 结束
[4]      op       uint8     0x01 = SET，0x02 = DELETE
[5:9]    key_len  uint32
[9:13]   val_len  uint32    DELETE 固定为 0
[13:21]  ttl      float64   绝对过期时间戳（秒），0.0 表示永不过期
```

之后是 key（utf-8，key_len 字节）和 value（utf-8，val_len 字节）。写的时候先算好整条记录再一次性写下去，读的时候按同样的结构解。

解码函数碰到任何一处不对——crc32 校验不过、长度非法、数据不够、op 未知、utf-8 解不出来——都不抛异常，直接返回 `None`，交给上层当坏记录处理，不搞「解到一半抛异常再 catch」那套。编解码和段文件读写都在 `backend/app/kv/datafile.py`，这一层不碰 TTL 语义，也不碰内存索引，是纯字节层，所以能单独拿去做测试。

## 写路径

写入永远落在段文件末尾：文件用 `a+b` 打开，追加写，读的时候自己 seek 到目标偏移，两者互不干扰。一条记录写完调一次 `file.flush()`，再把内存里的 KeyDir（`key -> (段号, value 偏移, 长度, 过期时间)`）和 LRU 读缓存更新掉，返回成功。

段文件有大小上限（默认 8 MiB）。活跃段再写会超过阈值就先滚一个新段；单条记录本身就超阈值的话，让它独占一个新段，不会出现「滚了段还是装不下」的死循环。

## 为什么只 flush 不 fsync

这是个取舍，如实记一下：这里调的是 `flush()`，不是 `fsync()`。

`flush()` 只是把 Python 缓冲区的数据交给操作系统。进程崩了（Ctrl+C、kill -9、异常退出）数据还在，因为已经进了内核页缓存；但整机掉电时，内核还没来得及把脏页写盘，最后几条就可能没了。`fsync()` 能把数据真正按到盘上，代价是每次写都等一次磁盘 IO，写吞吐掉得很难看。这个项目是本地单机跑在 SSD 上的课程项目，权衡下来选了 flush。

所以「掉电也不丢最后几条」这件事，现在做不到；真要做到，下一步得把 flush 换成 fsync，或者做成可配置的刷盘策略（每条刷 / 定时刷）。这两个都没有，所以这里写的是限制，不是特性。

## 顺序和坏尾恢复

顺序上有一件事不能反：先写盘，再改内存。反过来的话，两者之间挂掉时内存已经认为写成功了、段文件里却没有，重启就丢了。

恢复在引擎构造时做，把所有段文件按编号升序扫一遍重放：

- SET：键没过期就写进 KeyDir，过期就跳过；
- DELETE（tombstone）：把该键从 KeyDir 移除；
- 坏记录：停止扫这一段，把段截断到最后一条有效记录的结束偏移。

「坏尾」是这么来的：段文件是追加写的，如果写到一半被打断，尾巴上就会留下不完整的字节。扫描器扫到第一条解不出来的记录，就认为它以及它后面的全是垃圾，不再往后读，直接把文件 truncate 回最后一个有效记录的位置。这样重放出来的引擎状态就是完整的。生成器 `scan()` 会把「最后一条有效记录的结束偏移」放进返回值，恢复流程用 `except StopIteration as e: e.value` 拿到它。

## compaction

段文件只追加，所以同一个键改多次就会留下多条历史记录。`POST /kv/compact` 干的事是把「每个存活键一堆历史记录」压成「每个存活键一条最新记录」：遍历 KeyDir 收集还活着的 (key, value, 过期时间)，顺手清掉过期的；把这些记录顺序写进数据目录下的临时子目录 `_compact`，再关掉旧段句柄、把新段逐个覆盖移动回数据目录、删掉编号超出的旧段和临时目录；最后用新映射整体替换 KeyDir，读缓存清空重建。键的段号和偏移全变了，所以读缓存必须整体清掉，这一步不能省。整个 compaction 全程持有引擎那把锁，会短暂阻塞读写，单进程场景可以接受。

## 现在的状态

恢复是用反复 kill 进程、打断写入的方式测过的，重放回来的数据对得上。段文件本身就是追加日志这件事，现在也写在 `backend/app/kv/engine.py` 的文件头注释里，免得以后再有人按「WAL + 快照」去理解它。
