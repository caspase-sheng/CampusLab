做「后端挂了」的验证时，我以为会看到请求直接失败、走 fetch 的 catch。实际屏幕上显示的是「请求失败（HTTP 500）」，请求是正常 resolve 的，只是状态码 500。这一下和直觉对不上，回头翻了代理配置才想明白。

## 500 是 Vite 代理给的

frontend/vite.config.ts 里配了 `server.proxy`，把 /api 和 /kv 都转发到 `http://127.0.0.1:8000`。浏览器只跟开发服务器 5173 打交道，请求由 Vite 在服务端转给 8000。

后端没启动的时候，Vite 拿着这个请求去连 8000，连不上。它没有让这个请求在网络层失败，而是自己回了一个 HTTP 500。所以浏览器收到的始终是一个真实的响应，有状态码、有 body，只是这个响应是代理发出来的，不是后端发的。

## fetch 会正常 resolve

因为拿到了响应，fetch 会 resolve，不会 reject。`response.ok` 是 false，`response.status` 是 500。代码如果只写了 catch 去兜底，这一路根本不会进 catch，会直接落到非 2xx 的分支。

## client.ts 里区分了两种失败

frontend/src/api/client.ts 把两类失败分开了：

- fetch reject：`ApiError` 的 status 设成 0，表示压根没连上服务器——后端没起、断网、请求被拒这类；
- 非 2xx：带上服务器返回的真实状态码，比如 500、401。

`ApiError` 上的 status 字段就是为这个区分准备的。看到 0 就知道是连通性问题，看到具体码就知道服务器确实回话了。

## 什么时候才是 status 0

只有在没有代理、或者直连后端失败的情况下，才会是 status 0。配了代理的项目里，后端没起这条路会被代理截住，变成 500，不会落到「无法连接服务器」那一句。验证「后端挂了」的时候，屏幕上出现哪句话，得先知道代理在中间插了一手。
